# Review of the bonding curves and pools, 2026-10-18

An AI-assisted code review (Claude Code), not an independent human audit. It does not replace the audit that `BONDING_CURVE.md`, `BONDING_CURVE_EVM.md` and `ARETIA_POOL*.md` call for before real money.

Scope: `contracts-evm/AretiaCurve.sol` (deployed on Ethereum, BNB Chain and Polygon at `0x4e85bc5bd6f08fa87ceb749372e34226556837e8`), `contracts-evm/AretiaPool.sol`, `contracts-evm/AretiaTokenFactory.sol` (deployed), `program/aretia-curve` (planned for mainnet as `CCBr6Dty…`), `program/aretia-curve-grad`, `program/aretia-pool` (devnet), and the `curve-math` and `pool-math` crates.

## Findings

| # | Severity | Where | Finding | Status |
|---|---|---|---|---|
| 1 | High (blocks a launch for good) | `aretia-curve`, `aretia-curve-grad`: `create_curve` | The curve's token vault was created with `init`. It is the associated token account of the curve address, and anyone may open an associated account for any owner, including an address that holds nothing yet. A stranger who opens it first (about 0.002 SOL) makes `create_curve` fail with "Provided owner is not allowed" for that token, for good. **Reproduced against the committed `aretia_curve.so` in LiteSVM.** | Fixed in source (`init_if_needed`). Regression test `a_stranger_cannot_block_a_curve_by_opening_its_vault_first`. **The committed binary predates the fix**: see `artifacts/*.STALE`. |
| 2 | High (blocks a pool for good) | `aretia-pool`: `create_pool` | The same for both pool vaults (the token vault and the wrapped-SOL vault). Regression test `a_stranger_cannot_block_a_pool_by_opening_its_vaults_first`. Binary marked stale. |
| 3 | Medium (holders' money frozen 7 days, launch never graduates) | Solana curves: `migrate` | The graduation pool's address is fixed by the token (Meteora's customizable pool, or the Aretia Pool for `aretia-curve-grad`). The program already allowed `abort_migration` after 7 days, but holders could not sell during that week. | Mitigated in source: `abort_migration` takes the pool account as an optional extra account, and when that pool already exists under its program it unwinds at once. The web flow passes the pool and offers the unwind straight away. Regression test `a_pool_someone_else_opened_first_lets_holders_unwind_at_once`. Preventing the squat itself needs a pool whose address the attacker cannot take first (for example a Meteora config with a pool-creator authority); not done. |

## Checked and sound

- **Curve maths** (`curve-math`, `AretiaCurve.sol`): fee rounded up, outputs and new reserves rounded against the trader, `v_sol - real_sol == v_sol0`, k never falls, and sells are bounded by `real_sol` and by `curve_tokens`. No overflow in the stated ranges.
- **Solvency**: both Solana programs check the vault against what they owe after every move. The EVM contracts check `balance >= totalOwed`. Donations only add.
- **Reentrancy (EVM)**: every value-moving function is locked, and state is written before calls. Only factory tokens (plain ERC-20, no hooks) are accepted.
- **Token checks (Solana)**: raw mint bytes are read: no mint or freeze authority, and only metadata extensions, so no transfer hook, fee, permanent delegate or non-transferable mint gets through.
- **`AretiaPool.sol`**: fee credits never sum to more than was collected, reserves stay under 2^112, LP shares equal `l`, and locked shares can never be lowered.
- **`aretia-pool`**: positions are bound to their owner and pool, ids can't be squatted (they must be the owner's address or sign), and claims pay only a wrapped-SOL account owned by the named recipient.
- **`AretiaTokenFactory.sol`**: no owner, exact fee forwarded in the same call, and supply minted once.

## Before deploying the Solana curve or pool

1. Rebuild each program from the current source (`cargo build-sbf`). Run its LiteSVM suite against the new build, including the regression tests above; all must pass. This review could not build SBF here because the Solana tool download is blocked.
2. Replace the `.so` and its `.sha256`, and delete the `.STALE` marker. `curve-solana-mainnet.mjs` and `pool-solana-mainnet.mjs` refuse to prepare a deploy while the marker is there.
3. The 1.7 SOL deploy in the handover must use the rebuilt binary, not the one committed before this review.
